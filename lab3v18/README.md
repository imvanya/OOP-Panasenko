# Лабораторна робота №3 — Реалізація IDisposable та паттерну Dispose (Варіант 18)

## Про проєкт
У цій лабораторній роботі я реалізував власний клас `MyMemoryStream`, який імітує потік у пам'яті. Головна мета — розібратися з правильним управлінням ресурсами в .NET за допомогою інтерфейсу `IDisposable`, деструктора та збирача сміття (`Garbage Collector`).

## Реалізація

### Поля та властивості
Для імітації роботи потоку додано приватні поля `_buffer` (байт-масив), `_isOpen` (стан) та прапорець `_disposed` для відстеження звільнення ресурсів. Також створив властивості `IsOpen` та `Capacity`.

### Конструктор та роботи з даними
Конструктор `MyMemoryStream(int size)` виділяє пам'ять під буфер та відкриває потік. Методи `Write(byte[] data)` та `Read()` відповідають за запис і читання. Перед кожною операцією проводиться перевірка, чи не був потік закритий.

### Патерн Dispose
Реалізовано стандартний механізм очищення ресурсів:
* `Dispose(bool disposing)` — захищений метод, який звільняє буфер і закриває потік.
* `Dispose()` — публічний метод інтерфейсу, що викликає `Dispose(true)` та відключає фіналізацію через `GC.SuppressFinalize(this)`.
* `~MyMemoryStream()` — деструктор, який викликає `Dispose(false)` на випадок, якщо `Dispose()` не викликали вручну.

### Демонстрація в Main
У програмі продемонстровано три варіанти роботи з об'єктом:
1. Через конструкцію `using`.
2. З явним викликом `.Dispose()`.
3. Без виклику `Dispose()` — перевірка автоматичного спрацювання деструктора через `GC.Collect()`.
